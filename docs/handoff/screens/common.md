# Common: what every screen needs

## Rules every screen follows

- A screen gets its ViewModels from the widget tree: `BasaScope.of(context)` → `AppViewModels` (both builds, `lib/ui/basa_scope.dart`; short names: `.crla`, `.aralClass`, `.auth`, ...) and, in admin-build screens only (under `lib/ui/admin/`), `AdminScope.of(context)` → `AdminViewModels` (`.users`, `.sf1Import`, `.syncReview`, ...). The bundles hold ViewModels only (no repositories).
- A screen calls ViewModels and reads models. It never imports `core/services/`, `core/data/`, `core/wiring/`, `core/repositories/`, `supabase` or `sqflite` (`dart run tool/check_vm_boundary.dart` fails the build).
- ViewModels are request/response: none is a `ChangeNotifier` or a stream. The screen owns its loading, error and refresh state, and calls the method again after a change.
- The build is fixed by the entry point: `lib/main.dart` (admin build: admins, coordinators) or `lib/main_tutor.dart` (tutor build). A tutor-build screen never imports an admin file (`dart run tool/check_tutor_imports.dart`).
- Every ViewModel method checks the sign-in itself. Refusals come as `ViewModelException`; its `message` is written for the user and is shown as is.

### Signed-in user
Build: both    Roles: all
Purpose: show who is signed in, their role and school; choose what the screen offers.
Calls:
- `AuthViewModel.currentUser` → `User?` (`email`, `fullName`, `role`, `schoolId`; superadmin = admin with `schoolId == null`)
- `AuthViewModel.isSignedIn`, `isOffline`, `mustChangePassword` → `bool`
- `SchoolViewModel.loadAll()` then `items` → `List<School>` — the school's name for `schoolId`
Live previews: none.
Errors: none (getters).
Console: `whoami`

### Pickers
Build: both    Roles: all
Purpose: choose a school, section, class, learner, school year, round or region by name.
Calls:
- `SchoolViewModel.loadAll()` → `items: List<School>` (schools the user may see, online) and `localSchools()` → `List<School>` (device copy, works offline; e.g. to name a section's school)
- `SectionViewModel.localSections()` → `List<Section>` (device copy; `Section.toString()` = grade + name) and `loadAll()` → `items` (online)
- `StudentViewModel.localStudents(sectionId)` → `List<Student>`; `loadForSection(sectionId)` (online)
- `AralClassViewModel` class list (see `aral.md`)
- `DashboardViewModel.schoolYears()` → `List<String>` (latest first)
- rounds: `PhilIriRound.values`, `CrlaRound.values` (`core/models/`, each has `label`)
- regions: `Region` (`core/models/region.dart`, `Region.byId`)
Live previews: none.
Errors: not signed in.
Console: `school-list`, `school-list-local`, `list-sections`, `section-list`, `list-students`, `student-list-section`, `aral-classes`, `dashboard-years`

### Online / offline and pending work
Build: both    Roles: all
Purpose: show whether the device works offline, what waits to be uploaded, and that records in a pending upload are read-only.
Calls:
- `AuthViewModel.isOffline` → `bool`
- `SyncViewModel.preview()` → `SyncPreview` (unsent work), `uploads()` → `List<SyncUploadRow>` (see `sync.md`)
- Not available yet: asking "is this record locked by a pending upload?" before the user edits it. The ViewModel refuses the write, and its message says so.
Live previews: none.
Errors: a write on a locked record is refused by the ViewModel (message shown as is).
Console: `sync-preview`, `sync-status`

### Version refusal
Build: both    Roles: all
Purpose: when sign-in is refused because the server and the app are on different BASA releases, say which side must update.
Calls:
- `AuthViewModel.signIn(...)` → `String?` error (the refusal text), `versionWarning` → `String?`
Live previews: none.
Errors: the refusal text itself.
Console: `sign-in`, `version-check`

### Error display
Build: both    Roles: all
Purpose: one rule for showing failures.
Calls: any.
Errors: `ViewModelException` → show `message`. Any other exception (server or database error) → show `unexpectedErrorMessage` (`core/models/messages.dart`) and log the detail (`debugPrint`); never show the exception text.
Console: the console prints `"<what> failed: $e"`; a screen must not.

### Export and print (every table)
Build: both    Roles: all (whoever sees the table)
Purpose: export the list **as shown** (after the screen's own search, filters and sort) to Excel, with the footer
"Generated by <name> (<role>) on <date>, <time>". Excel only (owner and reading coordinator, 2026-11-28: Excel tables
copy into other workbooks and reports). Print, or a PDF, comes from Excel: File > Print / Save As PDF; every printed
page shows the footer on the left and "Page n of m" on the right.
```
[ Search...      ] [Grade ▾] [Section ▾]        [Export to Excel]
```
Calls:
- Build `ExportTable(title, school:, schoolYear:, filters:, columns:, rows:)` (`core/models/export_table.dart`) from
  what the screen shows: `filters` = plain lines of what is applied ("Grade 7, Rizal", "Search: cruz"), `columns` =
  `ExportColumn(label, kind:)` (`ExportColumnKind.number` only for real numbers; LRNs, codes and dates stay text),
  `rows` = the visible rows in the visible order (all pages of a paginated list, not only the current page), values
  String / num / null.
- `TableExportViewModel.xlsx(table)` → `List<int>` (the file's bytes); `fileName(table, 'xlsx')` →
  `"<title> 2026-11-28.xlsx"`. Save or share the bytes with the platform's file picker / share sheet (the team's
  choice of package).
- The footer is written by the ViewModel from the signed-in user and the device clock; a screen never types it.
- DepEd forms keep their own export buttons (CRLA2 scoresheet, ARAL Forms 1/2/4, Phil-IRI scoresheet template).
- **Excel only on screens (owner 2026-11-28): no screen offers a CSV download.** A CSV opened in Excel turns a
  12-digit LRN into `9.99E+11`. Every report that has a CSV method today is exported as Excel by passing its CSV
  text through two calls: `final t = tableExport.tableFromCsv(csv, '<title>', school:, schoolYear:, filters:);`
  then `tableExport.xlsx(t)`. The LRN column stays text and the file gets the footer. The CSV methods stay (BASA's
  imports and the console use them); only the screens stop handing out `.csv` files. The reports to switch:
  - `StudentViewModel.rosterCsv(sectionId)`: section roster
  - `AralViewModel.rosterCsv(...)`: ARAL roster
  - `AralReportViewModel.implementationReportCsv(...)`: ARAL implementation report (the DepEd-layout `.xlsx` stays
    as its own button)
  - `AralCheckinViewModel.checkinReportCsv(...)`: check-in report
  - `nlaReportCsv(report, filter)`, `progressReportCsv(report, ...)`, `bosyMasterlistCsv(list)`
    (`nla_report_viewmodel.dart`): NLA Form 2b, progress monitoring, BOSY masterlist
  - `srpListCsv(list, ...)`, `srpClassesCsv(classes)` (`srp_viewmodel.dart`): SRP candidates and classes
  - `philIriRankingCsv(r)` (admin build): Phil-IRI ranking
  Checked 2026-11-28 on the command pass's files: each is one table (header row + rows, a "SCHOOL TOTAL" row
  included) and converts cleanly. A list with no CSV method (users, schools, ...) builds its `ExportTable` directly.
Errors: `ViewModelException` (e.g. "A row has more values than the table has columns."): show `message`.
Console: `export-table` (turns any CSV the console wrote into this Excel file).
