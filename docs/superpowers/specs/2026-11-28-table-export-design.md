# Table export to Excel and PDF (M1-07, backend part)

Date: 2026-11-28. Owner approved approach A. Both builds. No migration, no tables.

## Intent

Every table in BASA can be searched, filtered and sorted on screen (the frontend team's part), and the list **as
filtered** can be exported to Excel or PDF and printed, with a footer saying who generated it and when. This piece
is the export: one call that every screen uses, so the footer and layout are the same everywhere and the team
doesn't build export ten times.

## Goals

- One export for any table: a screen passes what it shows (after its own search, filters and sort) and gets back
  the bytes of an `.xlsx` or a `.pdf` file.
- A plain report page: BASA, the table's title, school and school year when given, a line with the filters used,
  the table (header repeated on every PDF page), and the footer
  `Generated by <full name> (<role>) on 28 Nov 2026, 9:14 AM` + `Page 2 of 3` (PDF).
- Lists with no report today (all coordinators, all schools, users of one school) export the same way.
- Testable without screens: Dart tests and a console command.

## Non-goals

- Search, filters, sorting, pagination and the print dialog: screens (frontend team). Printing = the screen opens
  the PDF this returns (e.g. Flutter `printing`), which is the team's choice.
- DepEd forms keep their own templates and exports (CRLA2 scoresheet, ARAL Forms 1/2/4, Phil-IRI scoresheet
  template). The existing CSV exports stay unchanged.
- No new report contents: the export prints what it's given, it computes nothing.

## Anti-goals

- An export that shows other rows than the screen (the screen's filtered list is the source of truth).
- A footer that can be typed by the screen: the name, role and time come from the ViewModel (signed-in user, clock).
- Anything that needs Flutter in `core/` or a ViewModel.

## Approaches (owner picked A)

- **A. One shared export the screens hand their rows to (picked).** One ViewModel, an `ExportTable` model. Every
  table the same way, exactly what's on screen. Cost: each screen builds the table description.
- B. One export method per report, like the CSVs. 10+ methods; misses on-screen search/sort and plain lists.
- C. Screens make the files with Flutter packages. Footer/layout repeated per screen, nothing testable from the
  console or `test/`.

## Decisions

- **Model** (`core/models/export_table.dart`): `ExportTable(title, {school, schoolYear, filters, columns, rows})`.
  `filters` is a list of plain lines ("Grade 7, Section Rizal", "Search: cruz"); `columns` are `ExportColumn(label,
  {kind})` with kind `text` or `number`; `rows` are `List<List<Object?>>` (String / num / null; null = empty cell).
  A row shorter than the columns is padded with empties, a longer one is refused.
- **ViewModel** `TableExportViewModel` (both builds; wired in `wire_tutor.dart`): `xlsx(ExportTable, {DateTime? now})`
  and `pdf(ExportTable, {DateTime? now})` return `List<int>`; `fileName(ExportTable, String extension, {now})` gives
  `<title> 2026-11-28.xlsx` (characters a file name can't hold replaced). Each checks the sign-in first
  (`requireActiveSession`, offline works) and refuses with `notSignedInMessage`. `now` is for tests; the footer uses
  the device's local time.
- **Footer text**: `Generated by <users.full_name> (<role label>) on <d MMM yyyy>, <h:mm AM/PM>`; role label Admin
  / Coordinator / Tutor (superadmin = "Admin, region"). In Excel it is a line two rows below the table; in PDF it
  is at the bottom of every page with `Page n of m`.
- **Excel**: through the existing `xlsx_writer.dart` (no new package): one sheet named after the title (cut to
  Excel's 31 characters, forbidden characters removed); rows: `BASA — <title>`, school / school year line, filter
  lines, empty row, header, data, empty row, footer. Number columns as numbers, text columns as text (`@`, so an LRN
  keeps its digits). Column widths from the longest value (capped).
- **PDF**: new dependency `pdf` (pure Dart, Apache-2.0), standard Helvetica (Latin-1, covers ñ and accents; a
  character outside it is replaced, never an error). A4, portrait up to 6 columns, landscape from 7 (owner may
  change). Title block on page 1 only; the header row repeats on every page; long text wraps inside its cell.
  An empty table still exports (header + "No rows").
- **Console** (both builds, `table_export_commands.dart`): `export-table <in.csv> <out.xlsx|out.pdf> <title...>
  [school=<text>] [year=<text>] [filter=<text>]...`: reads a CSV the console wrote (first row = columns, a column is
  a number column when every non-empty cell is a number) and writes the file, printing its path and row count. Any
  existing CSV export command plus this one exports every report today without screens.
- **Handoff**: `docs/handoff/screens/common.md` gets an "Export and print" section: build `ExportTable` from the
  rows on screen, call `xlsx`/`pdf`, save or share the bytes, print = open the PDF.

## Package risk (checked 2026-11-28, dry run)

`pdf` 3.13 needs `xml` ^7 (BASA is on ^6.6.1), so the resolver takes **`pdf` 3.12.0**, which moves `archive` back
from 4.5.2 to 4.0.9 (through `image`) and adds `barcode`, `bidi`, `image`, `qr`. `archive` is what every BASA
`.xlsx` reader and writer uses (SF1, CRLA scoresheet, Phil-IRI workbook/scoresheet, ARAL forms). Gate: the full
`flutter test` must pass after the change, with the xlsx tests read closely. If it doesn't, stop and bring the
choice back (upgrade `xml` to 7 for `pdf` 3.13 instead, or keep PDF out). `build_release.ps1`'s `third_party/`
check covers only `excel2003`, unaffected.

## Left to the builder

- Exact cell widths, font sizes, margins, the em dash in the title (any Latin-1-safe choice).
- How the PDF test checks content (e.g. an uncompressed document for the test, or the page count).
- The CSV reading helper for the console command (reuse `table_reader.dart` / `csv.dart` if they fit).
