# Demo Data (Night City world) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One command builds the Night City demo world (2 schools, 2 school years, about 40 learners per section) on a chosen server through the app's own ViewModels, and reports, line by line, that every built feature has data to show.

**Architecture:** Pure-Dart generators (`world`, `records`, `dates`) decide *what* exists from a fixed seed and are unit-tested against the app's own scoring rules. A `DemoSession` opens one command-pass `Device` per account and exposes its wired ViewModels. Phase files write the world in order (setup, rosters, CRLA, Phil-IRI, ARAL, next year, leftovers), uploading and approving through sync. A coverage step reads the counts back and writes the report and the walkthrough kit.

**Tech Stack:** Dart 3 (no Flutter), `package:basa_capstone` ViewModels, `tool/command_pass/device.dart`, `sf1_fixture.dart`, `excel_plus`, `flutter test` for the pure parts.

**Spec:** `docs/superpowers/specs/2026-11-24-demo-data-design.md`

## Global Constraints

- Schools: Night City Elementary School `NCES-DEMO` (Grades 1-6), Night City High School `NCHS-DEMO` (Grades 7-10); Region X (region id 13); division text `Night City Division`.
- School years `2025-2026` (complete) and `2026-2027` (up to the run date). No record dated after the run date.
- One section per grade per year, about 40 learners each (draw 36-44); same section names both years.
- Grade 6 (ES) and Grade 10 (HS) of 2025-2026 leave; Grade 1 and Grade 7 of 2026-2027 are new and are assessed at BOSY like everyone.
- Accounts: `demo.super@nightcity.test` (admin, no school), `coord.es@` / `coord.hs@`, `admin.es@`, three tutors per school (`tutor1.es@` ... `tutor3.hs@`, at least one internal + one external), all `@nightcity.test`.
- Passwords and server config only in `D:\0_CAPSTONE\verify\demo\` (`accounts.json`, `supabase_config.json`); never in the repo, never printed.
- LRNs: `9991` + 8 digits; never collide with command-pass LRNs (`9990...`).
- Materials link to `https://example.org/basa-demo/<slug>`.
- Every write goes through a ViewModel (or a console command where named); no SQL writes, no service role.
- `--config <path>` is required; the builder prints the server URL and asks for `yes` before writing.
- Code lives in `tool/demo_data/`, tests in `test/tool/demo_data/`. Branch `excelsior`.
- After every task: `dart analyze` (no new errors), `dart run tool/check_tutor_imports.dart`, `dart run tool/check_vm_boundary.dart`.

## Review Focus

1. **A run that stops halfway is run again** -> it continues and creates no duplicates (Task 5 state file + per-step existence checks; test in Task 5, checked live in Task 12).
2. **The run date moves** (built next week instead of today) -> no session, check-in, IRIP week or assessment lands after the run date (Task 4 tests with two run dates).
3. **The wrong server** -> without `--config` the builder refuses; with it, nothing is written before `yes` (Task 5 test).
4. **A generated record the app scores differently than planned** -> each target level is checked against the app's own rule functions before writing (Tasks 3 tests; Task 8/9 read the stored result back and count mismatches in the report).
5. **One upload too big** -> uploads are sent per section and round, below `maxPackageBytes` (Task 6 helper refuses to build a package over the limit and splits instead; test with a small limit).
