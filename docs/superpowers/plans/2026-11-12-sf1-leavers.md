# SF1 Leavers Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** When a section's SF1 is imported again, list learners who are no longer on it and let an admin/coordinator archive them (transferred out / dropped out), move them to another section of the same grade with this year's records, restore returners, and later anonymize long-archived learners.

**Architecture:** Two cloud migrations add enrollment statuses, the `enrollment_moves` history, `students.anonymized_at`, four SECURITY DEFINER functions (archive, move, restore, anonymize), a narrow tutor permission for learners who moved away, and `sync_apply` re-pointing. The SF1 importer's trial gains *moving from X* / *returning* rows and a *not on this SF1* block. A new admin-build `LearnerLeaversViewModel` calls the functions online (through a Supabase repository) and mirrors the returned rows to SQLite v44 under `withSyncBypass`.

**Tech Stack:** Dart (no Flutter in `lib/core` / `lib/viewmodels`), sqflite_common_ffi, Supabase Postgres (PG18 throwaway harness for tests), `supabase` client `.rpc`.

**Spec:** `docs/superpowers/specs/2026-11-12-sf1-leavers-design.md` (D1–D14). Read it before any task.

## Review Focus

1. **A learner moved twice in one year (X → Y → X)**: CRLA attempts moving back into X must be renumbered after the attempts X already holds, order kept, never a unique-key error. Test in Task 2 (PG) and Task 3 (sync re-point).
2. **A tutor's upload holding records for a moved learner AND an archived learner**: the archived one must stop the upload with the named message; nothing applied (moved records not half-applied). Test in Task 3.
3. **An LRN on section Y's SF1 that is active in X of another grade, or archived and already anonymized**: other grade → today's conflict (*other grade, can't move*); anonymized → its LRN no longer matches, plain *insert*. Never a move or restore offer. Test in Task 4.
4. **Archive/move while a pending upload holds the learner's records**, including an `update` record keyed on an existing server row (no `student_id` in the payload row): refused, naming the upload. Test in Task 2.
5. **Anonymize eligibility at the edges**: archived exactly `archive_keep_months` ago (not yet eligible: strictly more), school year not ended (refused even if old), one enrollment still active in another year (refused). Test in Task 2.
